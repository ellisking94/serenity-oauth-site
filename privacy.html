Privacy Policy

This policy describes the intended handling of Google account data by Serenity Knowledge Automation, a private, owner-operated Google Drive-to-social-media workflow.

1. Who operates the service?

The service is operated privately for the Serenity Knowledge brand by its account owner. It is not offered as a public multi-user service. For questions or requests, contact the administrator through the contact details displayed on the Google OAuth consent screen, or through the project contact page. Do not post confidential information in public GitHub issues.

2. Google data requested and used

With the account owner's permission, the connector may access Google Drive file identifiers, names, file metadata and file contents needed to locate the authorised Serenity media folder, upload approved media assets, check their integrity and obtain media URLs. The exact Google Drive permissions requested are displayed by Google during authorisation. No Gmail, contacts, calendar, or advertising-data access is part of this connector.

3. Purpose of use

The workflow uses Google Drive access only to host and verify Serenity Knowledge content approved for social publishing, and to pass relevant approved asset URLs to the owner's Buffer account. Files outside the intended workflow should not be processed. Google data is not used for advertising, behavioural profiling, or training general-purpose AI models by this connector.

4. Where information is processed and stored

Google Drive files remain in the owner's Google Drive. The authorised automation may temporarily download/upload media to complete validation. OAuth configuration and refresh tokens, where used, are intended to be kept in restricted GitHub Actions secrets, not committed to public repositories. GitHub Actions logs and short-lived workflow artifacts may contain operational metadata such as file IDs, checksums, dates and delivery statuses; secrets must never be printed in logs. The owner controls the GitHub repository and connected accounts.

5. Sharing and disclosure

Approved media files may be made accessible by direct link so Buffer can retrieve them for publication. Such media may then appear on Instagram, Facebook and TikTok according to the owner's instructions. Private Drive files, OAuth secrets, and unrelated account content are not intentionally shared or published. Google, GitHub and Buffer operate under their own privacy and security terms when the workflow uses their services. We do not sell Google user data.

6. Retention and deletion

The account owner manages media retention in Google Drive and workflow records in GitHub. Temporary processing files are removed when ephemeral automation runners are disposed of, subject to any GitHub artifact/log retention settings. The owner can remove hosted files and workflow history from their respective services. Revoking Google account access prevents new authorised Drive API operations, but does not automatically delete previously published social media content.

7. Security and control

Access should use HTTPS, restricted credentials and least-privilege permissions where technically possible. Secrets must never be entered on this public website. This application cannot promise that third-party service providers never experience incidents. Review Google's permission screen carefully and authorise only if you recognise this workflow.

8. Your choices

The Google account owner can review or revoke access at Google Account → Third-party connections. They may also delete automation credentials stored in GitHub and remove authorised content from Google Drive. For data enquiries, use the contact method described above.

9. Changes

If the application's actual data practices change, this policy must be updated before those changes are deployed. Last updated: 9 October 2026.
